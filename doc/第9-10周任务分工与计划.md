## 七、协作规范（务必遵守）

1. **各人只在自己的分支开发**，不要直接改 `master`，由组长统一合并。
2. **改完先 commit，再 push**。上阶段的教训：只在本地编辑、没有 commit 的改动，**别人完全拿不到**（仓库里根本不存在）；commit 完全离线，任何情况下都先 commit。
3. **推送失败的处理**：
   - 报错含 `Failed to connect ... 443` / 超时 → 网络问题，开代理软件（Clash Verge 开 TUN 模式即可，不需要配端口），或把提交打包给组长代推；
   - 报错 `403` / 要求账号密码 → 权限或凭据问题，用 Personal Access Token 认证，或联系组长加权限。
4. **组长代推方式**：
   ```bash
   # 组员本地执行
   git bundle create 姓名.bundle 自己的分支名
   # 把 bundle 文件发给组长，组长执行
   git fetch 姓名.bundle 分支名:分支名
   git push origin 分支名
   ```
   作者信息保留组员本人，committer 为组长，属正常做法。
5. **提交信息格式**：`姓名: 做了什么`，可带标签，例如 `翟旌超: accounts 增加登录失败锁定与密码强度校验 #zjc`。
6. **提交内容**：只提交源码、测试、文档成品；**不要提交临时脚本、渲染中间图、工具原始输出**（上阶段有分支误提交了 100 多个 `_word_task` 中间文件）。
