## 四、关键验证证据

**N+1 消除实测（诊断脚本抓取的 SQL）**

改造前首页每增 1 篇文章多 2 条 SQL：

```sql
-- 每篇文章 1 条（卡片上 comment_set.count）
SELECT COUNT(*) AS "__count" FROM "comments_comment" WHERE article_id = ?
```

改造后首页 SQL 条数与文章数量无关（固定为「主查询 + tags 预加载 + comments 预加载」）。

**详情页关联访问**：主查询 1 + tags 1 + comments 1 = 3 条，标签 1 个与 6 个时相同。

## 六、全量测试中的 20 个既有问题（非本次改动引入）

在 SQLite 测试库下全量跑 321 个用例，有 20 个报错，根因是项目**既有的两处问题**：

| 问题 | 影响用例 | 根因 | 说明 |
|---|---|---|---|
| 旧式断言 API | `accounts.tests.AccountTest` 2 个 | `self.assertEquals(...)` 在 Python 3.12 已被移除（只剩 `assertEqual`） | 测试代码自身问题，与业务代码无关 |
| `EmailSendLog` 表名不一致 | 其余 18 个（邮件/注册/评论相关） | `servermanager/models.py` 声明 `db_table='email_send_log'`，但 `0001_initial.py` 建表时**没有带 db_table**，迁移建出的实际表名是 `servermanager_emailsendlog` | 模型与迁移不一致；在组员本地 MySQL（若手工建过 `email_send_log` 表）不会触发 |

**这两项都不在本次改动的文件范围内**（本次只动了 `djangoblog/` 下 5 把文件、`blog/views.py`、`djangoblog/settings.py`），建议后续：
1. 把 `accounts/tests.py` 的 `assertEquals` 改为 `assertEqual`（2 处，1 分钟即可改）；
2. `EmailSendLog` 二选一：给迁移补 `db_table='email_send_log'`，或删掉模型里的 `db_table` 声明。

> 本次未擅自修改这两处，避免影响其他组员正在开发的分支（按要求不改动无关文件）。
