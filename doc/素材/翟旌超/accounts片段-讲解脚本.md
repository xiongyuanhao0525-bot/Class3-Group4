## 二、录制前准备（一次性，约 5 分钟）

1. **启动演示服务器**：双击 `start-demo.ps1`（或右键“使用 PowerShell 运行”）。
   - 它会先重置演示状态，再启动 `http://127.0.0.1:8000`，5 秒后自动开浏览器。
   - 这个黑窗口**录制全程别关**——第 5 段要在里面展示验证码邮件。
2. **浏览器设置**（推荐 Edge / Chrome 新建窗口）：
   - `Ctrl + 0` 重置缩放（100%），`F11` 全屏，`Ctrl + Shift + B` 隐藏书签栏；
   - 关闭微信 / QQ / 邮件通知（右上角专注助手 → 仅闹钟）；
   - 只留 `localhost:8000` 一个标签页。
3. **录制工具**：
   - 最省事：`Win + G` 游戏栏 → 录制（默认录 1080p，麦克风需在设置里打开）；
   - 或 OBS：分辨率 1920×1080、30fps、窗口采集只抓浏览器、麦克风 + 桌面音频。
4. **试录 10 秒**：确认画面是 1080p、声音有波形、鼠标可见，然后删掉。
5. **口令速查**（演示用，都是准备好的）：
   - 演示账号：`zjc_demo` / `Blog@2026#Sec`
   - 找回密码邮箱：`zjc_demo@example.com`
   - 报告用的强密码：`Blog@2026#Sec`

> 每次都从「干净状态」开始：`start-demo.ps1` 已经重置过；如果中途 NG，另开一个窗口跑 `reset-demo.ps1`，再回浏览器 `F5`。

  > 下面一个个演示。

### 镜头 3｜00:22–01:05 功能一：密码强度校验
- **00:22 操作**：地址栏输入 `http://127.0.0.1:8000/register/`，回车。
- 口播：
  > 先看注册页。页面上的密码框下面直接给出了强度规则：8 到 64 个字符，至少包含三类字符……
- **00:30 操作**：用户名 `demo_try_1`，邮箱 `demo_try_1@example.com`，密码和确认都填 `password123`，点「创建账号」。
- 「密码确认」框下方出现红字：`密码至少需要包含 3 类字符（小写字母、大写字母、数字、特殊符号），当前 2 类，还缺少：大写字母、特殊符号`
- 口播：
  > 用一个只有小写字母和数字的弱口令试一下——被拦住了，而且它会告诉你缺哪一类字符。
- **00:38 操作**：把两个密码都改成 `Aaaa@2026`，再点「创建账号」。
- 「密码确认」框下方出现：`密码不能包含 4 个以上连续重复的字符（如 aaaa）`
- 口播：
  > 再试一个看着挺复杂、其实是四个 a 连着的密码，同样被拦，提示重复字符。
- **00:46 操作**：改成 `Blog@2026#Sec`（两个框都填），点「创建账号」。
- 结果：直接跳到首页，右上角变成已登录状态。
- 口播：
  > 换成真正强的密码就注册成功了，而且会自动登录。
  > 这套规则只写在 utils 里的一个函数里，注册和修改密码都调它，所以两边口径完全一致。

### 镜头 4｜01:05–01:45 功能二：登录失败锁定
- **01:05 操作**：右上角头像 → **退出登录**，然后进 `http://127.0.0.1:8000/login/`。
- 口播：
  > 第二个功能是防暴力破解。我先把账号退出，然后用错误密码连续登录。
- **01:10 操作**：用户名 `zjc_demo`，密码随便填 `Wrong@Pass2026`，点登录，**连续点 4 次**（每点一次停一下让观众看清提示）。
- 屏幕上依次出现：
  - 第 1 次：`用户名或密码错误，再失败 4 次后账号将被临时锁定 15 分钟`
  - 第 2 次：`再失败 3 次…`；第 3 次：`2 次`；第 4 次：`1 次`
- 口播：
  > 每次失败都会告诉用户还剩几次机会，这个次数是存在数据库里的。
- **01:28 操作**：第 5 次点登录 → 页面变成锁定提示：`该账号因连续登录失败已被临时锁定，请约 15 分钟后再试`
- 口播：
  > 第五次直接锁定，返回的是 429 状态码。
- **01:36 操作**：把密码改成正确的 `Blog@2026#Sec`，再点登录 —— 依然被拒，提示同一句。
- 口播：
  > 这时候即使密码是对的也进不去，必须等锁定结束。
  > 锁定状态同时写在缓存和数据库里，管理员还能在后台手动清零解锁。

### 镜头 5｜01:45–02:20 功能三：验证码重发倒计时 + 发送次数限制
- **01:45 操作**：进 `http://127.0.0.1:8000/forget_password/`，邮箱填 `zjc_demo@example.com`。
- 口播：
  > 第三个功能是找回密码的发码接口，防止有人拿脚本疯狂刷短信和邮件。
- **01:52 操作**：点「Get Verification Code」。
- 结果：按钮变灰，右侧出现 `Resend in 60s` 倒计时。
- 口播：
  > 点一下之后按钮立刻禁用，开始 60 秒倒计时。
- **02:00 操作**：按 `F5` 刷新页面（前端倒计时被清掉），**再点一次**按钮。
- 结果：出现红色提示 `请 60 秒后再获取验证码`（HTTP 429）。
- 口播：
  > 就算刷新页面绕过前端的倒计时，服务端照样会拦住，因为 60 秒的限制记在服务端。
  > 另外同一邮箱每小时最多发 5 次，用完就返回“获取过于频繁”。
- **02:08 操作**：`Alt + Tab` 切到 runserver 黑窗口，滚动到刚打印的验证码邮件。
- 口播：
  > 因为演示环境我把邮件改成了控制台输出，这里能看到刚才那封验证码邮件，验证码 5 分钟内有效。

## 四、录制小技巧

- 鼠标移动**放慢一倍**，点击前停顿半秒，观众才跟得上。
- 注册页提交失败后，用户名和邮箱会保留，**只需要改两个密码框**，不用从头填。
- 每次出现报错，**停留 2 秒**再继续操作，方便剪辑时卡点。
- 输入密码时可以用小眼睛图标切换明文，让观众看清填的是什么（可选）。
- 说错一句不要停，**整段重来**更省剪辑时间；重来前先跑 `reset-demo.ps1`。
- 锁定演示只能做**一次**（真实锁定 15 分钟）；已经锁了就跑 `reset-demo.ps1`，文件缓存是跨进程的，立刻生效。
- 录完先自己看一遍：能不能听清、画面有没有通知弹窗、片头是不是 5-8 秒。

## 六、常见问题

| 现象 | 处理 |
| --- | --- |
| `start-demo.ps1` 报端口被占用 | 关掉之前的 runserver 窗口，或改成 `runserver 127.0.0.1:8001`（地址栏 URL 也要改） |
| 登录页一进去就是「已锁定」 | 跑 `reset-demo.ps1`，再 `F5` |
| 点发码提示「请 60 秒后再获取」但我想重新演示 | 跑 `reset-demo.ps1`，再 `F5` |
| 页面样式错乱 | 多半是 `blog/static/blog/dist` 没构建：在 `frontend` 目录跑 `npm run build` |
| 开发者工具里 429 标红 | 正常，429 就是「太快了」的标准状态码，不用管 |
| 验证码在哪看 | runserver 黑窗口里，控制台打印的那封邮件的正文 |
