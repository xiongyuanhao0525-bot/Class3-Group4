## 一、录制前准备

**1. 建一个 GitHub OAuth App（约 5 分钟，只需一次）**

1. 打开 `https://github.com/settings/developers` → **OAuth Apps** → **New OAuth App**
2. 填写：
   - Application name：`DjangoBlog-demo`
   - Homepage URL：`http://127.0.0.1:8000`
   - Authorization callback URL：`http://127.0.0.1:8000/oauth/authorize`
3. 创建后复制 **Client ID**，再点 **Generate a new client secret** 复制密钥
4. 把这两个值发给杨杰翰，写入本地演示库的 `OAuthConfig`（只写 sqlite，不入仓库）

> 没有真实凭据就只能演示「绑定页 + 失败提示页」，无法演示绑定成功与解绑，片段会缺一半，建议务必建。

**2. 录屏与窗口**

- 录屏：`Win + G`（Xbox Game Bar，设置里选 1080p / 30fps）或 OBS（1920×1080、30fps、只捕获浏览器窗口）
- 浏览器：Edge 新窗口，只留一个标签页，隐藏书签栏，缩放 100%，关闭系统通知
- 鼠标：移动放慢，点击前停顿约 0.5 秒，避免甩动

**3. 启动演示环境**

```powershell
cd C:\Users\24566\Desktop\123456\Class3-Group4
$env:PYTHONPATH='C:\Users\24566\AppData\Local\Temp'; $env:DJANGO_SETTINGS_MODULE='shot_settings'
python manage.py runserver 127.0.0.1:8000
```

- 演示账号：`shotuser` / `Shot123456`
- 绑定页：`http://127.0.0.1:8000/oauth/bindings.html`
- 伪造 state（失败页）：`http://127.0.0.1:8000/oauth/authorize?type=github&code=fake-code&state=forged-state`

## 二、分镜与口播稿（合计约 1 分 50 秒）

> 片头 5–8 秒（3 班 4 组 + 全体成员姓名）由熊圆好统一制作，本片段不用录。

| 镜头 | 时间 | 画面操作 | 口播（照着念） |
|---|---|---|---|
| 1 | 0:00–0:12 | 打开 `/login/`，输入账号密码登录，进入首页 | 这是维护后的 DjangoBlog。我负责 oauth 第三方登录子系统的三项维护：state 校验加固、第三方账号绑定与解绑、授权失败的统一提示。 |
| 2 | 0:12–0:28 | 打开 `/oauth/bindings.html`，鼠标缓慢划过「已绑定」「可绑定」两块 | 这是本次新增的第三方账号管理页。用户可以在个人账号里看到已绑定的平台，也可以为未绑定的平台发起绑定，不必再靠反复登录去猜。 |
| 3 | 0:28–0:55 | 点 GitHub 行的「绑定」→ GitHub 授权页 → 点 Authorize → 跳回绑定页，GitHub 出现在「已绑定」 | 绑定走的是模板方法加多平台适配的结构：BaseOAuthManager 负责授权地址、换取 token、拉取用户信息三步，子类只覆盖平台差异。新增一个平台只需要实现三个方法。 |
| 4 | 0:55–1:15 | 鼠标移到「解绑」，点一次（POST 提交），看到提示 | 解绑必须走 POST，避免链接被预取或误点。同时加了保护：如果这是账号最后一个登录方式，不允许解绑，防止把自己锁在门外。 |
| 5 | 1:15–1:40 | 地址栏直接输入伪造 state 的回调地址，回车，出现 400「GitHub 授权失败」页 | 第二项是 state 校验。授权请求会带一次性 state，回调时必须与会话中的值一致；缺失、伪造或重放都会被拒绝。这里直接伪造 state 访问回调，系统返回 400，并给出可解释的中文提示，而不是静默跳回首页。 |
| 6 | 1:40–1:50 | 回到失败页，鼠标停在「返回首页」「重新授权」两个按钮上 | 第三项是把分散的失败分支收拢到一个统一出口，按类型给出提示并记录日志，用户可自助重试，运维也能定位。我的片段到此结束。 |

**语速参考**：每行口播约 4 字/秒，念快了就多停一下，后期可整体裁剪。
